= Créez et gérez des stratégies de sauvegarde Microsoft SQL Server dans NetApp Backup and Recovery
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
Utilisez NetApp Backup and Recovery pour créer des règles de sauvegarde Microsoft SQL Server qui contrôlent la fréquence, la planification et la conservation des sauvegardes.


NOTE: Certaines de ces options et sections de configuration ne sont pas disponibles pour toutes les charges de travail.

Si vous importez des ressources depuis SnapCenter, vous risquez de rencontrer des différences entre les stratégies utilisées dans SnapCenter et celles utilisées dans NetApp Backup and Recovery.  Voirlink:reference-policy-differences-snapcenter.html["Différences de politique entre SnapCenter et NetApp Backup and Recovery"] .

Vous pouvez atteindre les objectifs suivants liés aux politiques :

* Créer une politique de snapshot local
* Créer une politique de réplication vers le stockage secondaire
* Créer une politique pour les paramètres de stockage d'objets
* Configurer les paramètres de stratégie avancés
* Modifier les politiques
* Supprimer les politiques




[[view-policies]]
== Voir les politiques

. Dans le menu NetApp Backup and Recovery , sélectionnez *Politiques*.
. Examinez les détails de la stratégie. Par exemple :
+
** *Charge de travail* : Exemples incluent Microsoft SQL Server, ONTAP Volumes, VMware, KVM, Hyper-V, Oracle Database ou Kubernetes.
** *Type de sauvegarde* : les exemples incluent la sauvegarde complète et la sauvegarde du journal.
** *Architecture* : les exemples incluent l'instantané local, la distribution en éventail, la mise en cascade, le disque à disque et le disque vers le magasin d'objets.
** *Ressources protégées* : indique combien de ressources sur le total des ressources de cette charge de travail sont protégées.
** *Protection contre les ransomwares* : indique si la politique inclut le verrouillage des instantanés sur l'instantané local, le verrouillage des instantanés sur le stockage secondaire ou le verrouillage DataLock sur le stockage d'objets.






[[create-a-policy]]
== Créer une politique

Vous pouvez créer des stratégies qui régissent vos snapshots locaux, vos réplications vers un stockage secondaire et vos sauvegardes vers un stockage d'objets. Une partie de votre stratégie 3-2-1 consiste à créer un instantané des instances, bases de données, applications ou machines virtuelles sur le système de stockage *principal*.

*Rôle requis de la console NetApp* Super administrateur NetApp Backup and Recovery ou administrateur de sauvegarde NetApp Backup and Recovery. Si vous protégez des données stockées sur un cluster Cloud Volumes ONTAP, le rôle d'administrateur Cloud Volumes ONTAP est également requis. En savoir plus link:reference-roles.html["Rôles et privilèges de sauvegarde et de récupération"]. https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["En savoir plus sur les rôles d'accès à la NetApp Console pour tous les services"^].

.Avant de commencer
Si vous prévoyez de répliquer vers un stockage secondaire et souhaitez utiliser le verrouillage des instantanés sur des instantanés locaux ou sur un stockage secondaire ONTAP distant, vous devez d'abord initialiser l'horloge de conformité ONTAP au niveau du cluster. Ceci est une exigence pour activer le verrouillage des instantanés dans la règle.

Pour obtenir des instructions sur la façon de procéder, reportez-vous à https://docs.netapp.com/us-en/ontap/snaplock/initialize-complianceclock-task.html["Initialiser l'horloge de conformité dans ONTAP"^] .

Pour plus d'informations sur le verrouillage des instantanés en général, reportez-vous à https://docs.netapp.com/us-en/ontap/snaplock/snapshot-lock-concept.html["Verrouillage des instantanés dans ONTAP"^] .

.Étapes
. Dans le menu NetApp Backup and Recovery , sélectionnez *Politiques*.
. Depuis la page Politiques, sélectionnez *Créer une nouvelle politique*.
+
La page « Politiques » s'affiche.

. Saisissez les informations dans la section *Détails* :
+
** Type de charge de travail : sélectionnez *Microsoft SQL Server*.
** Entrez un nom de politique.
** Sélectionnez un agent de console dans la liste *Agent*.


. Saisissez les informations dans la section *Architecture de sauvegarde*. Choisissez le flux de données pour la sauvegarde dans la liste :
+
** *Répartition 3-2-1* : stockage principal (disque) vers stockage secondaire (disque) vers cloud (stockage objet). Elle crée plusieurs copies des données sur différents systèmes de stockage, tels que des configurations ONTAP vers ONTAP et ONTAP vers stockage objet. Il peut s'agir d'un stockage objet chez un fournisseur de cloud ou d'un stockage objet privé. C'est la meilleure option pour une protection des données et une reprise après sinistre optimales. Cette option n'est pas disponible pour Amazon FSx for NetApp ONTAP.
** *Cascade 3-2-1* : stockage principal (disque) vers stockage secondaire (disque) et stockage principal (disque) vers stockage cloud (stockage objet). Il peut s'agir d'un stockage objet fourni par un fournisseur de cloud ou d'un stockage objet privé tel que StorageGRID. Cela crée une chaîne de réplication des données sur plusieurs systèmes afin de garantir la redondance et la fiabilité. Cette option n'est pas disponible pour Amazon FSx for NetApp ONTAP.
** *Réplication disque à disque* : Stockage principal (disque) vers stockage secondaire (disque). La stratégie de protection des données ONTAP à ONTAP réplique les données entre deux systèmes ONTAP afin de garantir une haute disponibilité et une reprise après sinistre. Cela est généralement réalisé à l'aide de SnapMirror, qui prend en charge la réplication synchrone et la réplication asynchrone. Cette méthode permet de maintenir vos données à jour et disponibles sur plusieurs sites pour une forte protection des données.
** *Stockage disque vers objet* : Stockage principal (disque) vers le cloud (stockage objet). Cela réplique les données d’un système ONTAP vers un système de stockage objet. Il peut s’agir d’un stockage objet d’un fournisseur de cloud ou d’un stockage objet privé tel que StorageGRID. Cette méthode est idéale pour la conservation des données à long terme et l’archivage. Cette option n’est pas disponible pour Amazon FSx for NetApp ONTAP.
** *Distribution disque à disque* : stockage principal (disque) vers stockage secondaire (disque) et stockage principal (disque) vers stockage secondaire (disque). Vous pouvez configurer plusieurs paramètres secondaires pour l’option de distribution disque à disque.
** *Instantanés locaux* : Instantané local du volume sélectionné. Cette opération crée des copies en lecture seule, à un instant précis, des volumes de production sur lesquels vos charges de travail s’exécutent. Vous pouvez utiliser les instantanés locaux pour récupérer d'une perte de données ou de données corrompues, ainsi que pour créer des sauvegardes en vue d’une reprise après sinistre.


. Fournissez des informations pour la section *Paramètres de snapshot local* :
+
** Sélectionnez l'option *Ajouter une planification* pour choisir la ou les planifications d'instantanés. Vous pouvez avoir un maximum de cinq planifications.
** *Fréquence des instantanés* : Sélectionnez la fréquence horaire, quotidienne, hebdomadaire, mensuelle ou annuelle.
** *Conservation des instantanés* : saisissez le nombre d'instantanés à conserver.
** *Activer la sauvegarde des journaux* : Activez cette option pour sauvegarder les journaux et définir la fréquence et la durée de conservation des sauvegardes des journaux. Pour ce faire, vous devez avoir préalablement configuré une sauvegarde des journaux. Voir link:br-start-configure.html["Configurer les répertoires de journaux"].


. Fournissez des informations pour la section *Paramètres secondaires* (réplication vers un stockage secondaire) :
+
** *Sauvegarde* : sélectionnez la fréquence horaire, quotidienne, hebdomadaire, mensuelle ou annuelle.
** *Cible de sauvegarde* : sélectionnez le système cible sur le stockage secondaire pour la sauvegarde.
** *Durée de verrouillage des instantanés* : Indiquez si vous souhaitez activer la protection contre toute falsification des instantanés. Si cette option est activée, saisissez le nombre de jours, de mois ou d’années pendant lesquels vous souhaitez verrouiller l’instantané.
** *Transfert vers le stockage secondaire* : Choisissez quand transférer les instantanés vers le stockage secondaire.
+
*** L’option *Planification des transferts ONTAP - En ligne* est sélectionnée par défaut, ce qui signifie que les instantanés sont transférés immédiatement vers le système de stockage secondaire. Il n’est pas nécessaire de planifier la sauvegarde.


** *Utiliser la relation secondaire existante SnapMirror et SyncMirror* : activez cette option pour utiliser la relation existante SnapMirror ou SyncMirror afin de transférer les instantanés vers le cluster de destination.


. Fournissez des informations pour la section *Paramètres de stockage d'objets* (sauvegarde sur le stockage d'objets) :
+

NOTE: Les champs qui s'affichent diffèrent selon le fournisseur et l'architecture sélectionnés.

+
** *Fournisseur* : Sélectionnez le fournisseur de votre système de stockage d’objets et saisissez les identifiants dans les champs appropriés (les champs d’identifiants diffèrent selon le fournisseur).
** *Cible de sauvegarde* : Sélectionnez une cible de stockage d’objets enregistrée et vérifiez qu’elle est accessible dans votre environnement de sauvegarde.
** *Espace IP* : sélectionnez l'espace IP à utiliser pour les opérations de sauvegarde.  Ceci est utile si vous avez plusieurs espaces IP et que vous souhaitez contrôler lequel est utilisé pour les sauvegardes.
** *Paramètres de planification* : sélectionnez la planification qui a été définie pour les instantanés locaux.  Vous pouvez supprimer une planification, mais vous ne pouvez pas en ajouter une, car les planifications sont définies en fonction des planifications d'instantanés locaux.
** *Copies de conservation* : Saisissez le nombre d’instantanés à conserver pour chaque planification.
** *Planification des transferts pour le stockage objet* : Choisissez la planification des transferts ONTAP pour sauvegarder les données sur le stockage objet.
** * Hiérarchisez vos sauvegardes du magasin d'objets au stockage d'archivage* : si vous choisissez de hiérarchiser les sauvegardes vers le stockage d'archivage (par exemple, AWS Glacier), sélectionnez l'option de hiérarchisation et le nombre de jours d'archivage.


. Vous pouvez également configurer les paramètres avancés dans la stratégie.
+
[%collapsible]
====
** *Sauvegarde par copie uniquement* : Choisissez la sauvegarde par copie uniquement (un type de sauvegarde Microsoft SQL Server) si vous devez sauvegarder vos ressources à l’aide d’une autre application de sauvegarde.
** *Paramètres du groupe de disponibilité* : sélectionnez les réplicas de sauvegarde préférés ou spécifiez un réplica particulier. Ce paramètre est utile si vous disposez d’un groupe de disponibilité SQL Server et que vous souhaitez contrôler le réplica utilisé pour les sauvegardes.
** *Vérification des sauvegardes* : Sélectionnez si vous souhaitez activer la vérification des sauvegardes et si vous la souhaitez immédiatement ou ultérieurement. Cette fonctionnalité garantit que les sauvegardes sont valides et peuvent être restaurées avec succès. Nous vous recommandons d’activer cette option pour garantir l’intégrité de vos sauvegardes. Par défaut, la vérification des sauvegardes s’effectue à partir du stockage secondaire si le stockage secondaire est configuré. Si le stockage secondaire n’est pas configuré, la vérification des sauvegardes s’effectue à partir du stockage principal.
+
Configurez également les options suivantes : ** *Quotidienne*, *Hebdomadaire*, *Mensuelle* ou *Annuelle* vérification : si vous avez choisi *Plus tard* comme vérification de sauvegarde, sélectionnez la fréquence de vérification des sauvegardes. Cela garantit que les sauvegardes sont régulièrement vérifiées pour leur intégrité et peuvent être restaurées avec succès. ** *Étiquettes de sauvegarde* : choisissez un niveau de sauvegarde dans vos règles dont vous souhaitez vérifier les sauvegardes. Selon votre paramètre *Vérifier sur le secondaire*, la liste des niveaux provient soit de vos planifications principales, soit de vos planifications secondaires. Les sauvegardes horaires et les sauvegardes de journaux n'apparaissent pas car elles ne sont pas éligibles à la vérification. ** *Contrôle de cohérence de la base de données* : vous pouvez, si vous le souhaitez, sélectionner les limites à appliquer aux contrôles de cohérence de la base de données avant la sauvegarde.

** *SnapMirror format du volume et de l’instantané* : Choisissez parmi les options suivantes :
+
*** *Utiliser un format de nom personnalisé pour les copies d'instantané* : Choisissez un schéma de nommage pour les instantanés. Si ce champ est laissé vide, un horodatage est ajouté à la fin de chaque nom d'instantané.
*** *Indiquez le format du volume SnapMirror* : Spécifiez un préfixe, un suffixe ou les deux pour modifier le nom de volume SnapMirror par défaut. Par défaut, un volume SnapMirror hérite du nom du volume source.


** *Débit de transfert maximal* : Pour laisser l'utilisation de la bande passante illimitée, sélectionnez *Illimité*. Si vous souhaitez limiter le débit de transfert, sélectionnez *Limité* et sélectionnez la bande passante réseau entre 1 et 1 000 Mbps allouée au transfert des sauvegardes vers le stockage objet. Par défaut, ONTAP peut utiliser une quantité illimitée de bande passante pour transférer les données de sauvegarde des volumes du système vers le stockage objet. Si le trafic de sauvegarde affecte les charges de travail, réduisez la bande passante réseau pour les transferts.
** *Tentatives de sauvegarde* : Pour relancer la tâche en cas d’échec ou d’interruption, sélectionnez *Activer les nouvelles tentatives en cas d’échec*. Indiquez le nombre maximal de tentatives pour les tâches de création d’instantanés et de sauvegarde, ainsi que l’intervalle de temps entre les tentatives. Le nombre de tentatives doit être inférieur à 10.
+

TIP: Si la fréquence de snapshot est fixée à une heure, le délai maximal, additionné au nombre de tentatives, ne doit pas dépasser 45 minutes.

** *Analyse anti-ransomware* : Sélectionnez si vous souhaitez activer l’analyse anti-ransomware sur chaque compartiment. Cela nécessite le verrouillage DataLock sur le stockage objet. Indiquez la fréquence de l’analyse en jours. Cette option s’applique au stockage objet AWS et Microsoft Azure. Cette option peut entraîner des frais supplémentaires, selon le fournisseur de cloud.
** *Notification* : Choisissez d’activer ou non les notifications par e-mail pour les opérations de sauvegarde. Vous pouvez sélectionner les événements qui déclenchent une notification — par exemple, lorsqu’une sauvegarde réussit, échoue ou se termine avec des avertissements.


====
. Une fois terminé, sélectionnez *Créer*.




[[edit-a-policy]]
== Modifier une politique

Vous pouvez modifier l'architecture de sauvegarde, la fréquence de sauvegarde, la politique de rétention et d'autres paramètres d'une politique. Pour les politiques de charge de travail Kubernetes, vous pouvez uniquement modifier les paramètres de planification et de rétention.

Vous pouvez ajouter un autre niveau de protection lorsque vous modifiez une politique, mais vous ne pouvez pas supprimer un niveau de protection.  Par exemple, si la politique protège uniquement les snapshots locaux, vous pouvez ajouter la réplication au stockage secondaire ou les sauvegardes au stockage d'objets.  Si vous disposez de snapshots et de réplications locaux, vous pouvez ajouter un stockage d'objets.  Cependant, si vous disposez de snapshots locaux, de réplication et de stockage d'objets, vous ne pouvez pas supprimer l'un de ces niveaux.

Si vous modifiez une politique qui sauvegarde sur un stockage d’objets, vous pouvez activer l’archivage.

Si vous avez importé des ressources depuis SnapCenter, vous pourriez constater des différences entre les règles utilisées dans SnapCenter et celles utilisées dans NetApp Backup and Recovery. Voir link:reference-policy-differences-snapcenter.html["Différences de politique entre SnapCenter et NetApp Backup and Recovery"].

*Rôle de NetApp Console requis*

Super administrateur NetApp Backup and Recovery ou administrateur de sauvegarde NetApp Backup and Recovery. https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["En savoir plus sur les rôles d'accès à la NetApp Console pour tous les services"^]

.Étapes
. Dans la NetApp Console, accédez à *Protection* > *Backup and Recovery*.
. Sélectionnez l’option *Politiques*.
. Sélectionnez la politique que vous souhaitez modifier.
. Sélectionnez les *Actions*image:icon-action.png["Icône Actions"] icône et sélectionnez *Modifier*.
. Une fois la modification terminée, sélectionnez *Terminé*.
. Dans la boîte de dialogue de confirmation, saisissez le nom de la policy pour confirmer les modifications.
+
L'enregistrement des modifications affecte toutes les applications protégées par cette politique.

. Sélectionnez *Terminé* pour confirmer.




[[delete-a-policy]]
== Supprimer une politique

Vous pouvez supprimer une politique si vous n’en avez plus besoin.


TIP: Vous ne pouvez pas supprimer une politique associée à une charge de travail.

.Étapes
. Dans la NetApp Console, accédez à *Protection* > *Backup and Recovery*.
. Sélectionnez l’option *Politiques*.
. Sélectionnez la politique que vous souhaitez supprimer.
. Sélectionnez les *Actions*image:icon-action.png["Icône Actions"] icône et sélectionnez *Supprimer*.
. Confirmez l'action et sélectionnez *Supprimer*.
