== Gérer les informations de l'hôte

Gérez les informations des hôtes pour garantir que les bons hôtes sont protégés. Consultez, modifiez et supprimez les informations des hôtes selon vos besoins.

*Rôle requis dans la NetApp Console* : super administrateur NetApp Backup and Recovery, administrateur de sauvegarde NetApp Backup and Recovery, administrateur de restauration NetApp Backup and Recovery, ou administrateur de clonage NetApp Backup and Recovery. Si vous protégez des données stockées sur un cluster Cloud Volumes ONTAP, le rôle d’administrateur Cloud Volumes ONTAP est également requis. https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["En savoir plus sur les rôles d'accès à la NetApp Console pour tous les services"^]

* Configurez le répertoire des journaux. Pour plus de détails, consultez link:br-start-setup.html["Configurer les paramètres de NetApp Backup and Recovery"].
* Suspendre les horaires
* Modifier un hôte
* Supprimer un hôte




[[manage-hosts]]
=== Gérer les hôtes

Vous pouvez gérer les hôtes détectés dans votre système, individuellement ou en groupe.


TIP: Pour gérer un hôte, recherchez le statut « Non géré » dans la colonne Hôtes. NetApp Backup and Recovery gère déjà les hôtes dont le statut est « Géré ».

Une fois que vous avez géré les hôtes dans NetApp Backup and Recovery, SnapCenter ne gère plus les ressources sur ces hôtes.

*Rôle requis de la NetApp Console* Super administrateur de NetApp Backup and Recovery ou administrateur de sauvegarde de NetApp Backup and Recovery. Si vous protégez des données stockées sur un cluster Cloud Volumes ONTAP, le rôle d'administrateur Cloud Volumes ONTAP est également requis. https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["En savoir plus sur les rôles d'accès à la NetApp Console pour tous les services"^]

.Étapes
. Dans le menu, sélectionnez *Inventaire*.
. Sélectionnez une charge de travail pour afficher les détails de protection.
. Sélectionnez l'icône Actionsimage:../media/icon-action.png["Option Actions"] > *Voir les détails*.
. Sélectionnez l'onglet *Hôtes*.
. Sélectionnez un ou plusieurs hôtes. Si vous sélectionnez plusieurs hôtes, une option *Actions groupées* apparaît. Sélectionnez *Gérer (jusqu'à 5 hôtes)*.
. Sélectionnez l'icône Actionsimage:../media/icon-action.png["Option Actions"] > *Gérer*.
. Examiner les dépendances de l’hôte :
+
** Si le vCenter ne s’affiche pas, sélectionnez l’icône en forme de crayon pour ajouter ou modifier les détails du vCenter.
** Si vous ajoutez un vCenter, vous devez également enregistrer le vCenter en sélectionnant *Enregistrer vCenter*.


. Sélectionnez *Valider les paramètres* pour tester vos paramètres.
. Sélectionnez *Gérer* pour gérer l'hôte.




[[suspend-schedules]]
=== Suspendre les horaires

Suspendez les planifications pour arrêter les opérations de sauvegarde et de restauration pendant la maintenance de l'hôte.

.Étapes
. Dans le menu NetApp Backup and Recovery , sélectionnez *Inventaire*.
. Sélectionnez l’hôte sur lequel vous souhaitez suspendre les planifications.
. Sélectionnez les *Actions*image:icon-action.png["Icône Actions"] icône et sélectionnez *Suspendre les programmes*.
. Dans la boîte de dialogue de confirmation, sélectionnez *Suspendre*.

[[protect-database-instances]]
=== Protéger les instances de base de données

Attribuez une stratégie à une instance de base de données afin de gérer la planification et la conservation de la protection des ressources.

.Étapes
. Dans le menu NetApp Backup and Recovery , sélectionnez *Inventaire*.
. Sélectionnez la charge de travail que vous souhaitez afficher et sélectionnez *Afficher*.
. Sélectionnez l'onglet *Instances*.
. Sélectionnez l'instance.
. Sélectionnez les *Actions*image:icon-action.png["Icône Actions"] icône et sélectionnez *Protéger*.
. Sélectionnez une politique ou créez-en une nouvelle.
+
Pour plus de détails sur la création d'une politique, voir link:br-use-policies-create.html["Créer une politique"].

. Fournissez les scripts à exécuter avant et après la sauvegarde.
+
** *Pré-script* : Indiquez le nom et l’emplacement du fichier de script à exécuter automatiquement avant le démarrage de l’action de protection. Utilisez cette option pour effectuer des tâches ou des configurations supplémentaires avant le workflow de protection.
** *Post-scriptum* : Indiquez le nom et l’emplacement du fichier script à exécuter automatiquement une fois l’action de protection terminée. Utilisez-le pour effectuer des tâches ou des configurations supplémentaires après le workflow de protection.


. Fournissez les informations de vérification pour l'instantané :
+
** Emplacement de stockage : sélectionnez où stocker l’instantané de vérification.
** Ressource de vérification : sélectionnez si vous souhaitez vérifier la ressource sur l’instantané local, sur le stockage secondaire ONTAP ou sur les deux.
** Calendrier de vérification : Sélectionnez la fréquence : horaire, quotidienne, hebdomadaire, mensuelle ou annuelle.
