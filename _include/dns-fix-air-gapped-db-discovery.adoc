Si vous utilisez le déploiement local de NetApp Console dans un environnement isolé où les hôtes de base de données ne sont pas accessibles via le DNS standard, vous devez temporairement modifier la configuration interne de CoreDNS de RKE2. Cela permet aux pods de résoudre des noms d’hôtes spécifiques en adresses IP au sein du cluster, de la même manière que l’ajout d’entrées à  `/etc/hosts` sur un nœud.


IMPORTANT: Avant d'apporter des modifications, vérifiez à la fois la configuration CoreDNS existante et le  `rke2-coredns-config.yaml` HelmChartConfig existant afin d'éviter d'écraser des personnalisations déjà en place. Sur la plupart des nœuds de déploiement local NetApp Console, ce fichier existe déjà et contient déjà des demandes de ressources. Si le fichier existe déjà, ne le recréez pas ; ajoutez uniquement le bloc  `servers:` à l'existant  `valuesContent`. Appliquez cette modification à l'aide des manifestes RKE2 afin qu'elle continue d'être gérée de manière cohérente par l'opérateur et l'environnement d'exécution RKE2.

.Avant de commencer
* Dans la mesure du possible, maintenez le fichier HelmChartConfig sous contrôle de modification.
* Utilisez un nom de fichier clair afin que l'objectif de la substitution CoreDNS soit évident.
* Si l'enregistrement DNS attendu n'est pas visible dans le fichier Corefile, vérifiez les journaux du serveur RKE2 et confirmez la syntaxe du fichier manifeste.


.Étapes
. Vérifiez la configuration CoreDNS existante pour vous assurer que vous ne remplacez pas une modification existante :
+
[source, shell]
----
kubectl -n kube-system get cm rke2-coredns-rke2-coredns -o jsonpath='{.data.Corefile}'
----
. Vérifiez que le fichier HelmChartConfig existe :
+
[source, shell]
----
sudo cat /var/lib/rancher/rke2/server/manifests/rke2-coredns-config.yaml
----
+
[role="tabbed-block"]
====
.Si le fichier existe
--
.. Exécutez le script suivant pour ajouter le bloc  `servers:` au fichier HelmChartConfig existant :
+
[source, shell]
----
MANIFEST=/var/lib/rancher/rke2/server/manifests/rke2-coredns-config.yaml

# 1. Back up first
sudo cp -a "$MANIFEST" "$MANIFEST.bak.$(date +%Y%m%d-%H%M%S)"

# 2. Safety checks: valuesContent must be the last key, no servers: block yet
grep -n 'servers:' "$MANIFEST"        # must return nothing
tail -c 1 "$MANIFEST" | od -c | head  # file must end with a newline

# 3. Append ONLY the servers block (nothing above it changes)
sudo tee -a "$MANIFEST" >/dev/null <<'YAML'
    servers:
    - zones:
      - zone: .
      port: 53
      plugins:
      - name: errors
      - name: health
        configBlock: |-
          lameduck 10s
      - name: ready
      - name: kubernetes
        parameters: cluster.local in-addr.arpa ip6.arpa
        configBlock: |-
          pods insecure
          fallthrough in-addr.arpa ip6.arpa
          ttl 30
      # ───────────────────────── EDIT BELOW ─────────────────────────
      # Static DNS records for hosts the corporate DNS cannot resolve.
      # Format:  <IP>  <FQDN>  [optional aliases...]
      # `fallthrough` MUST stay as the last line -- it lets every other
      # name go to the upstream resolver via the `forward` plugin below.
      - name: hosts
        configBlock: |-
          1.2.3.4 example.domain.com exampleshortname
          fallthrough
      # ───────────────────────── EDIT ABOVE ─────────────────────────
      - name: prometheus
        parameters: 0.0.0.0:9153
      - name: forward
        parameters: . /etc/resolv.conf
      - name: cache
        parameters: 30
      - name: loop
      - name: reload
      - name: loadbalance
YAML

# 4. Confirm the merged result
sudo cat "$MANIFEST"
----
.. Vérifiez que la seule modification apportée au fichier HelmChartConfig est l'ajout du bloc  `servers:`.


--
.Si le fichier n'existe pas
--
.. Modifiez la zone  `configBlock` du script suivant et ajoutez vos enregistrements DNS statiques. Cela crée un fichier YAML HelmChartConfig dans le dossier des manifestes de RKE2, que RKE2 applique automatiquement pour remplacer la configuration CoreDNS :
+
[source, shell]
----
sudo tee /var/lib/rancher/rke2/server/manifests/rke2-coredns-config.yaml >/dev/null <<'YAML'
apiVersion: helm.cattle.io/v1
kind: HelmChartConfig
metadata:
  name: rke2-coredns
  namespace: kube-system
spec:
  # NOTE: This is a HelmChartConfig that *overlays* values onto the rke2-coredns
  # HelmChart already managed by RKE2. RKE2 watches /var/lib/rancher/rke2/server/manifests
  # and will re-render the rke2-coredns Helm release whenever this file changes.
  #
  # The `servers:` list below REPLACES the chart's default server definition,
  # so every plugin that was in the stock Corefile must be present here.
  # Do NOT delete plugins you don't recognize -- they are required for cluster DNS.
  valuesContent: |-
    servers:
    - zones:
      - zone: .
      port: 53
      plugins:
      - name: errors
      - name: health
        configBlock: |-
          lameduck 10s
      - name: ready
      - name: kubernetes
        parameters: cluster.local in-addr.arpa ip6.arpa
        configBlock: |-
          pods insecure
          fallthrough in-addr.arpa ip6.arpa
          ttl 30
      # ───────────────────────── EDIT BELOW ─────────────────────────
      # Static DNS records for hosts the corporate DNS cannot resolve.
      # Format:  <IP>  <FQDN>  [optional aliases...]
      # `fallthrough` MUST stay as the last line -- it lets every other
      # name go to the upstream resolver via the `forward` plugin below.
      - name: hosts
        configBlock: |-
          1.2.3.4 example.domain.com exampleshortname
          fallthrough
      # ───────────────────────── EDIT ABOVE ─────────────────────────
      - name: prometheus
        parameters: 0.0.0.0:9153
      - name: forward
        parameters: . /etc/resolv.conf
      - name: cache
        parameters: 30
      - name: loop
      - name: reload
      - name: loadbalance
YAML
sudo chmod 600 /var/lib/rancher/rke2/server/manifests/rke2-coredns-config.yaml
----
.. Copiez et exécutez le script.


--
====
. Vérifiez que CoreDNS a bien pris en compte la modification :
+
[source, shell]
----
kubectl -n kube-system get cm rke2-coredns-rke2-coredns -o jsonpath='{.data.Corefile}'
----
+
Si la modification n'est pas visible après quelques minutes, redémarrez le déploiement de CoreDNS puis vérifiez à nouveau le fichier Corefile :

+
[source, shell]
----
kubectl -n kube-system rollout restart deploy/rke2-coredns-rke2-coredns
----
. Si vous devez supprimer les entrées après avoir découvert les hôtes de la base de données, procédez comme suit :
+
[role="tabbed-block"]
====
.Si vous avez ajouté à un fichier existant
--
.. Restaurez le fichier sauvegardé ou supprimez uniquement le bloc  `servers:` du fichier :
+
[source, shell]
----
sudo cp -a /var/lib/rancher/rke2/server/manifests/rke2-coredns-config.yaml.bak.<timestamp> \
/var/lib/rancher/rke2/server/manifests/rke2-coredns-config.yaml
----
+
Ne supprimez pas le fichier, car il contient les paramètres de réglage des ressources RKE2 existants.

.. Après la restauration du fichier, supprimez les entrées hôtes. Les entrées obsolètes peuvent entraîner des problèmes de détection des hôtes et de sauvegarde planifiée.
.. Redémarrez le déploiement CoreDNS :
+
[source, shell]
----
kubectl -n kube-system rollout restart deploy/rke2-coredns-rke2-coredns
----


--
.Si vous avez créé un nouveau fichier
--
.. Supprimez le fichier HelmChartConfig du dossier des manifestes :
+
[source, shell]
----
sudo rm /var/lib/rancher/rke2/server/manifests/rke2-coredns-config.yaml
----
.. Après avoir supprimé le fichier, supprimez les entrées hôtes. Les entrées obsolètes peuvent entraîner des problèmes de découverte des hôtes et de sauvegarde planifiée.
.. Redémarrez le déploiement CoreDNS :
+
[source, shell]
----
kubectl -n kube-system rollout restart deploy/rke2-coredns-rke2-coredns
----
