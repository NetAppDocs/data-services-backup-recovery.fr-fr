== Classes de stockage d'archivage S3 prises en charge pour NetApp Backup and Recovery

Lorsque les fichiers de sauvegarde sont initialement créés, ils sont stockés dans le stockage S3 _Standard_. Ce niveau est optimisé pour le stockage des données rarement consultées, tout en permettant un accès immédiat. Après 30 jours, les sauvegardes passent à la classe de stockage S3 _Standard-Infrequent Access_ afin de réduire les coûts.

Si vos clusters sources exécutent ONTAP 9.10.1 ou une version ultérieure, vous pouvez choisir de hiérarchiser les sauvegardes vers le stockage _S3 Glacier_ ou _S3 Glacier Deep Archive_ après un certain nombre de jours (généralement plus de 30 jours) pour une optimisation supplémentaire des coûts.  Vous pouvez définir cette valeur sur « 0 » ou sur 1 à 999 jours.  Si vous le définissez sur « 0 » jours, vous ne pourrez pas le modifier ultérieurement sur 1 à 999 jours.

Les données stockées dans ces niveaux ne sont pas immédiatement accessibles en cas de besoin, et leur récupération engendre des coûts plus élevés. Vous devez donc tenir compte de la fréquence à laquelle vous pourriez avoir besoin de restaurer des données à partir de ces fichiers de sauvegarde archivés. Consultez la section relative à la restauration des données à partir du stockage d'archivage.

* Si vous ne sélectionnez aucun niveau d'archivage dans votre première politique de sauvegarde lors de l'activation de NetApp Backup and Recovery, _S3 Glacier_ sera votre seule option d'archivage pour les politiques futures.
* Si vous sélectionnez _S3 Glacier_ dans votre première politique de sauvegarde, vous pouvez alors passer au niveau _S3 Glacier Deep Archive_ pour les futures politiques de sauvegarde de ce cluster.
* Si vous sélectionnez _S3 Glacier Deep Archive_ dans votre première politique de sauvegarde, ce niveau sera le seul niveau d'archivage disponible pour les futures politiques de sauvegarde pour ce cluster.


Lorsque vous configurez NetApp Backup and Recovery avec ce type de règle de cycle de vie, ne configurez aucune règle de cycle de vie lors de la configuration du compartiment dans votre compte AWS.

== Restaurer les données à partir du stockage d'archives

Bien que le stockage d’anciens fichiers de sauvegarde dans un système d’archivage soit beaucoup moins coûteux que le stockage Standard ou Standard-IA, l’accès aux données d’un fichier de sauvegarde dans un système d’archivage pour les opérations de restauration prend plus de temps et coûte plus cher.

Combien coûte la restauration des données d'Amazon S3 Glacier et d'Amazon S3 Glacier Deep Archive ?:: Vous pouvez choisir parmi trois niveaux de priorité de restauration lors de la récupération de données depuis Amazon S3 Glacier, et deux niveaux de priorité lors de la récupération de données depuis Amazon S3 Glacier Deep Archive. S3 Glacier Deep Archive coûte moins cher que S3 Glacier :
+
--
[cols="25,25,25,25"]
|===
| Niveau d'archivage 3+| Restaurer la priorité et le coût 


|  | *Haut* | *Standard* | *Faible* 


| *Glacier S3* | Récupération la plus rapide, coût le plus élevé | Récupération plus lente, coût moindre | Récupération la plus lente, coût le plus bas 


| *Archives S3 Glacier Deep* |  | Récupération plus rapide, coût plus élevé | Récupération plus lente, coût le plus bas 
|===
Chaque méthode a des frais de récupération par Go et des frais par demande différents.  Pour connaître les tarifs détaillés de S3 Glacier par région AWS, visitez le https://aws.amazon.com/s3/pricing/["Page de tarification Amazon S3"^] .

--
Combien de temps faudra-t-il pour restaurer mes objets archivés dans Amazon S3 Glacier ?:: Le temps total de restauration comporte deux parties :
+
--
* *Temps de récupération* : temps nécessaire pour récupérer le fichier de sauvegarde depuis l’archive et le placer dans le stockage Standard. Ce temps est parfois appelé « réhydratation ». Le temps de récupération varie selon la priorité de restauration que vous choisissez.
+
[cols="25,20,20,20"]
|===
| Niveau d'archivage 3+| Restaurer la priorité et le temps de récupération 


|  | *Haut* | *Standard* | *Faible* 


| *Glacier S3* | 3 à 5 minutes | 3 à 5 heures | 5 à 12 heures 


| *Archives S3 Glacier Deep* |  | 12 heures | 48 heures 
|===
* *Durée de restauration* : Temps nécessaire pour restaurer les données à partir du fichier de sauvegarde stocké dans le stockage Standard. Cette durée n'est pas différente de celle d'une restauration classique effectuée directement depuis le stockage Standard lorsque vous n'utilisez pas de niveau d'archivage.
+
Pour plus d'informations sur les options de récupération d'Amazon S3 Glacier et S3 Glacier Deep Archive, reportez-vous à https://aws.amazon.com/s3/faqs/#Amazon_S3_Glacier["la FAQ d'Amazon sur ces classes de stockage"^] .



--


[NOTE]
====
La restauration d'un volume ou d'un fichier à partir d'un stockage d'archive peut prendre plus de temps. La tâche reste *En cours* dans le Moniteur de tâches pendant que Backup and Recovery réessaie la restauration en fonction de la priorité sélectionnée. Surveillez la restauration dans le *Moniteur de tâches* ; elle se termine lorsque la tâche atteint un état final, tel que *Terminée* ou *Échec*, après toutes les tentatives de restauration. Ne lancez pas une autre restauration à moins que la tâche n'échoue finalement.
