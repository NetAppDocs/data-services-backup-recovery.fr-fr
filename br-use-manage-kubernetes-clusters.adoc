= Gérez les clusters Kubernetes dans NetApp Backup and Recovery
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
NetApp Backup and Recovery vous permet de découvrir et de gérer vos clusters Kubernetes afin de protéger les ressources hébergées par les clusters.

.Rôle de NetApp Console requis
Administrateur d'organisation ou administrateur SnapCenter . link:reference-roles.html["En savoir plus sur les rôles d'accès à NetApp Backup and Recovery"] . https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["En savoir plus sur les rôles d'accès à la NetApp Console pour tous les services"^] .


NOTE: Pour découvrir les clusters Kubernetes, reportez-vous àlink:br-start-discover.html["Découvrez les charges de travail Kubernetes"] .



[[edit-kubernetes-cluster-information]]
== Modifier les informations du cluster Kubernetes

Vous pouvez modifier un cluster si vous devez changer son nom.

.Étapes
. Dans NetApp Backup and Recovery, sélectionnez *Inventaire* > *Clusters*.
. Dans la liste des clusters, choisissez un cluster que vous souhaitez modifier et sélectionnez le menu Actions associé.
. Sélectionnez *Modifier le cluster*.
. Apportez les modifications nécessaires au nom du cluster. Ce nom doit correspondre à celui utilisé avec la commande Helm lors de la découverte.
. Sélectionnez *Terminé*.




[[remove-a-kubernetes-cluster]]
== Supprimer un cluster Kubernetes

Pour arrêter la protection d'un cluster Kubernetes, désactivez la protection et supprimez les applications associées, puis supprimez le cluster de NetApp Backup and Recovery.  NetApp Backup and Recovery ne supprime pas le cluster ni ses ressources ; il supprime uniquement le cluster de l'inventaire de la NetApp Console .

.Étapes
. Dans NetApp Backup and Recovery, sélectionnez *Inventaire* > *Clusters*.
. Dans la liste des clusters, choisissez un cluster que vous souhaitez modifier et sélectionnez le menu Actions associé.
. Sélectionnez *Supprimer le cluster*.
. Vérifiez les informations dans la boîte de dialogue de confirmation et sélectionnez *Supprimer*.




[[upgrade-trident-protect]]
== Mettre à niveau Trident Protect

Pour les clusters Kubernetes exécutant Trident Protect 26.05 ou une version ultérieure, vous pouvez mettre à niveau Trident Protect directement depuis NetApp Backup and Recovery. L'option de mise à niveau n'apparaît que si une version plus récente est disponible.

.Étapes
. Dans NetApp Backup and Recovery, sélectionnez *Inventaire* > *Clusters*.
. Choisissez un cluster Kubernetes à mettre à niveau, puis sélectionnez l'icône Actions image:../media/icon-action.png["Option Actions"] > *Mettre à niveau le cluster*.
. Dans la boîte de dialogue de mise à niveau, procédez comme suit :
+
.. Dans la liste, sélectionnez la version vers laquelle effectuer la mise à niveau.
.. Sélectionnez *Mise à niveau*.






[[reconnect-a-kubernetes-cluster-to-a-console-agent]]
== Reconnecter un cluster Kubernetes à un agent Console

Si l'adresse IP de votre agent Console change (par exemple, après un redémarrage), votre cluster Kubernetes perdra sa connexion à l'agent et vous devrez vous reconnecter.

.Étapes
. Dans NetApp Backup and Recovery, sélectionnez *Inventaire* > *Clusters*.
. Choisissez un cluster Kubernetes déconnecté, puis sélectionnez l'icône Action image:../media/icon-action.png["Option Actions"] > *Modifier le cluster* > *Reconnecter le cluster*.
. Dans la boîte de dialogue Reconnect cluster, copiez les instructions de la ligne de commandes et exécutez-les sur votre cluster.
+
Une fois la commande terminée, votre cluster devrait se reconnecter automatiquement.

. Sélectionnez *Fermer*.




[[migrate-a-kubernetes-cluster-to-a-new-console-agent]]
== Migrer un cluster Kubernetes vers un nouvel agent de console

Si votre agent Console est supprimé ou devient indisponible, migrez les clusters qui l'utilisent vers un nouvel agent afin d'éviter toute interruption de la protection des applications.

.Avant de commencer
* https://docs.netapp.com/us-en/console-setup-admin/concept-agent-install-options.html["Déployez un nouvel agent Console."^]
* Choisissez une stratégie de protection à utiliser avec le nouvel agent Console, link:br-use-policies-kubernetes-create.html#edit-a-policy["modifier la politique"^], et associez la stratégie de protection au nouvel agent Console.


.Étapes
. Dans NetApp Backup and Recovery, sélectionnez *Inventaire* > *Clusters*.
. Choisissez un cluster Kubernetes déconnecté, puis sélectionnez l’icône Action image:../media/icon-action.png["Option Actions"] > *Modifier le cluster* > *Gérer l’agent*.
. Dans la liste, sélectionnez un nouvel agent Console.
. Vérifiez les informations de l'agent pour vous assurer que le nouvel agent Console peut accéder aux systèmes, aux cibles de sauvegarde et aux cibles secondaires utilisées par les applications protégées sur ce cluster.
. Copiez les instructions de ligne de commandes pour chaque section et exécutez les commandes sur le cluster.
+
Cette opération recrée les secrets Kubernetes, redirige Trident Protect vers le nouvel agent Console et recharge les paramètres. Une fois les commandes exécutées, le cluster utilise le nouvel agent Console.

. Sélectionnez *Fermer*.
