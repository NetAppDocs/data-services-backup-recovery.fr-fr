Examinez les systèmes sources, les systèmes secondaires et les destinations de stockage d'objets que NetApp Backup and Recovery prend en charge pour les opérations de sauvegarde et de restauration sur l'ensemble des charges de travail.



[[supported-systems-for-backup-and-restore-operations]]
== Systèmes pris en charge pour les opérations de sauvegarde et de restauration

NetApp Backup and Recovery prend en charge les systèmes ONTAP et les fournisseurs de cloud public et privé.



[[supported-regions]]
=== Régions prises en charge

NetApp Backup and Recovery est pris en charge avec Cloud Volumes ONTAP dans de nombreuses régions Amazon Web Services, Microsoft Azure et Google Cloud.

https://bluexp.netapp.com/cloud-volumes-global-regions["En savoir plus en utilisant la carte des régions mondiales"^]



[[supported-backup-destinations]]

[[supported-restore-destinations]]
=== Destinations de restauration prises en charge

Vous pouvez restaurer des données à partir d'un fichier de sauvegarde, d'une machine virtuelle, d'une base de données ou d'une ressource Kubernetes située sur un système secondaire (un volume répliqué) ou dans un stockage objet (un fichier de sauvegarde) vers les systèmes suivants. Les instantanés résident sur le système source et ne peuvent être restaurés que sur ce même système.


NOTE: Wasabi est actuellement le seul fournisseur de stockage objet compatible S3 qualifié. Les autres fournisseurs compatibles S3 n'ont pas été validés.

Gardez à l'esprit les considérations suivantes relatives à la restauration :

* Les restaurations à partir de Cloud Volumes ONTAP (réplication) ne peuvent être effectuées que vers Cloud Volumes ONTAP. Cependant, Cloud Volumes ONTAP dans AWS prend également en charge la restauration vers Amazon FSx for NetApp ONTAP.
* Les restaurations à partir d’ONTAP sur site (réplication) ne peuvent être effectuées que vers ONTAP sur site.
* Les restaurations à partir d'Amazon FSx for NetApp ONTAP et de Google Cloud NetApp Volumes (réplication) propriétaires ne peuvent être effectuées que vers le système propriétaire correspondant.
* La restauration d'Amazon S3 vers Amazon FSx for NetApp ONTAP doit suivre cet ordre : Amazon S3 vers Cloud Volumes ONTAP, puis Cloud Volumes ONTAP vers Amazon FSx for NetApp ONTAP.



NOTE: Les références à « on-premises ONTAP system » incluent les systèmes FAS, AFF et ONTAP Select.
